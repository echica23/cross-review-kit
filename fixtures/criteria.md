# レビュー基準

レビュー対象を、根拠資料とこの基準だけを使って照合する。対象の作成経緯や会話履歴は使わない。根拠資料に無い要求を新たに課さない。

## 観点

1. 網羅: 根拠資料の各要求が、対象の中で確認できる状態になっているか。確認手順が無い要求は指摘する。
2. 整合: 対象の期待結果や手順が、根拠資料の要求と矛盾していないか。
3. 内部矛盾: 対象の中で、同じ条件に対する期待結果が食い違っていないか。
4. 参照: 対象が言及する要求IDなどが、根拠資料に存在するか。
5. 判定可能性: 期待結果が空、または合否を判断できない場合は指摘する。
6. 境界: 根拠資料が上下限を定める場合、その境界を外れた条件を対象が正しく扱っているか。境界ちょうどの正しい記述は指摘しない。

## 重大度

- critical: 根拠資料と矛盾する期待結果であり、不適合を適合と判定し得る。
- major: 要求の確認漏れ、存在しない参照、対象内部の矛盾。
- minor: 確認手順の曖昧さなど、合否の誤りには直結しない問題。
- info: 上記に当てはまらない改善余地。不具合の根拠が無い場合は使わない。

## 指摘の書き方

各指摘に次を含める。

- severity: 上記のいずれか。
- location: 対象ファイル名と項目IDなど、場所が特定できる記述。
- description: 何が問題か。
- evidence: 根拠資料または対象の、どの記述と照合したか。
- suggestion: 対象をどう直すか。根拠資料に合わせて書く。

指摘が無い場合は、指摘を作らず findings を空配列にする。

根拠資料に要求が無く、または対象を読めず、照合そのものができない場合は、欠落の指摘を作らない。レビュー不能として、読めないものまたは不足しているものを理由にする。要求が読めて、その確認が対象に無いだけのときは、通常の指摘にする。
