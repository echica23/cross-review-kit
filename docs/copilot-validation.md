# Copilot対応の状態と職場PCでの検証

## 現在の状態

プロバイダー選択、引数構築、応答の共通形式への変換、CLI確認、アクセス未検証時の停止を実装しています。
**Copilotでレビューを実行する機能は未完成です。CLIの導入だけでは有効になりません。**
`Test-ProviderAccess` は現在必ず失敗し、直接 `Invoke-ProviderReview` を呼んでも停止します。
これは「実機検証待ちの完成版」ではなく、アクセス検証と安全な起動の実装を残した土台です。

## 残っている実装

1. 職場のCLIバージョン、Windows、管理ポリシーで利用できる機能を確認する。
2. 認証を維持しつつ個人設定・履歴・メモリ・拡張機能を持ち込まない実行環境を用意する。
3. 作業フォルダの自動書き込み許可、開発ツール用の追加許可を抑制し、レビュー資料だけ読み取り可能にする。管理ポリシーは回避しない。
4. **レビュー用モデルを呼ぶ前に**、同じ実効ポリシーで内側の読み取り成功、外側の読み取り拒否、書き込み拒否を機械的に検証する方法を実装する。
5. 上記の成功を条件に非対話コマンドを接続する。`Get-CopilotReviewArguments` は候補であり、CLIに対する動作検証は未実施。

モデルに「外部を読めなかった」と答えさせるだけの検査、設定ファイルの存在だけの検査、手動の検証済みフラグでは代用しません。
ツール許可はOSのアクセス制御と同一ではありません。内蔵ファイルツールと子プロセスでは強制方法も異なります。
非対話での事前検証が実現できない場合は、停止を維持したまま設計を見直してください。

## 職場PCで最初に確認すること

`copilot --version`、`copilot help sandbox`、`copilot help config` の結果から対応機能を確認します。
認証情報やトークンは結果ファイル・チャット・Gitに記録しないでください。
この時点の `-Provider copilot` は、CLI不在なら準備失敗、CLIを確認できればアクセス検証未実装として失敗するのが正常です。

## 実装後の受け入れ条件

- 指摘なし・指摘あり・レビュー不能が共通結果形式で区別できる。
- 認証失敗、未対応オプション、不正応答、アクセス制限不成立で成功扱いしない。
- 内側の読み取り、外側の拒否、書き込み拒否が実際に成立する。
- 事前検証失敗時にレビュー用モデルを呼ばない。
- 元資料のハッシュが一致し、一時ファイルが片付く。
- プロバイダーとCLIバージョンを記録し、未知の実使用モデル名を推測しない。
- Codexへの自動フォールバックをしない。
